# db/ invariant registry

The `LDB-*` invariants for the layout-db service (`design/layout-db/`,
phase 1: `07-implementation-phase1.md`). This registry lives with the code
(it moves with `db/` when the service splits into its own repo, per
`00-plan.md` §7) rather than in the site's `design/INVARIANTS.md`, which
carries one pointer entry instead.

Every row here needs a test tagged `[LDB-*]` in its `test()`/`it()` title
under `db/tests/`; `tests/tools/invariants.test.ts` (LDB-T1) fails the
build when an id has no tagged test, or a tag names an id not in this
table. Each slice's PR adds its own rows (07 §6); this file starts with
the S1 rows only. LDB-T1's own rule leaves no room for a "retired, no
test" row (every id present still needs one), so a fully retired id is
simply deleted from the table below rather than left as a placeholder --
this paragraph is the retirement log instead.

**Retired by design/layout-db/21-formats.md (2026-09-11, F1 -- D5 deletes
the cmini export/`toCmini`/every alias; D10 deletes spark/1's free-form
`x`; D12 deletes the legacy carry-forward, the record migration and the
M1 strip route):**
- **LDB-F10** (`x` round-trip identity) -- `x` itself is gone; see
  LDB-F23 (MF-9) for its replacement.
- **LDB-F20** (the alias table and the wire-format relabel rule) --
  there are no aliases left to have a rule about.
- **LDB-F21** (legacy-stored rows read as spark via `storedAsSpark`) --
  no row is ever stored under a legacy format any more.
- **LDB-I2a** ("follows upstream" via the legacy historical-event rule)
  -- folded into LDB-I14's own restated wording (a plain field read now).
- **LDB-I12** (a magic-only PATCH doesn't count as "the latest write"
  for the legacy follow rule) -- the legacy rule it modified is gone;
  decision 6's underlying claim ("magic edits fork like any other write")
  was already just LDB-I14's ordinary rule with no special case for
  `kind`.
- **LDB-P12** (the record migration) -- deleted outright; after the D8
  wipe every stored row is already spark/1 from the moment it's written.

**Retired by design/layout-db/26-no-board.md (2026-09-13 -- spark/1 has no
`board` field; saltorbit: a record says where its keys sit, never what board
it is drawn on):**
- **LDB-F31** (`fromCmini` maps cmini's board word by a fixed table) --
  there is no board word to map; `fromCmini` drops cmini's `board` outright
  (LDB-F23's dropped-field list, LDB-F40).

**Retired by LEDGER.md L4 (2026-09-12, design/layout-db/review/PROPOSAL.md
§2.1 -- "no consumer, ~2.5k src + ~4k test lines of surface for a spark/2
and third parties that don't exist"; nothing the bot or akl.gg called
lived here):**
- **LDB-H1** (webhook delivery at-least-once/in-order) -- the whole
  webhook subsystem (`core/webhooks.ts`, `routes/webhooks.ts`, the
  `webhooks` table) is deleted; the bot's keep-warm moves to the
  long-poll `GET /v1/changes?wait=` (LDB-CH1..CH5, below) once spark
  adopts it (Wave 2 B3).
- **LDB-H2** (the SSE stream reproduces the feed) -- `routes/stream.ts`
  and the `STREAM_*` vars are deleted; the long-poll replaces its
  keep-warm role.
- **LDB-H4** (a webhook secret never leaves the `webhooks` table) -- no
  `webhooks` table, no secret, nothing left to leak.
- **LDB-H5** (a drain's D1-write shape) -- no drain.
- **LDB-H6** (the claim-before-send lease) -- no lease, no drain.
- **LDB-P3** (a webhook-only follower matches a feed-only follower) --
  no webhook-only follower exists to build; the feed is still the one
  source of truth (LDB-P6 and this file's own `tests/events/feed.test.ts`
  "feed" describe cover what's left).
- **LDB-D5** (the Fly restore drill's report shape) -- `db/drill/` and
  `POST /v1/admin/drill` are deleted; `tests/rehost.test.ts` (LDB-G1) is
  the one remaining rehost proof, run in-CI daily.
- **LDB-D6** (per-major dump files, `latest.<name>-<N>.json`) -- no
  consumer was ever wired to fetch them; deleted along with
  `buildLatestMajorFiles`. The main dump (`latest.json`,
  `dump-YYYY-MM-DD.json.gz`, the monthly copy) is unchanged.
- **LDB-C3** (`[env.preview]` mirrors the top level) -- there is one
  layoutdb, production; the preview environment and its wrangler block
  are deleted (H13).
