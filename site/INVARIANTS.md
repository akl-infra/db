# db/site/ invariant registry

The `SITE-*` invariants for akldb.org (`design/akldb-site/01-plan.md` §5,
W1a). This registry lives with the site's own code -- it is not swept by
`cd db && npm test` (`db/vitest.config.ts`'s projects only glob `db/tests/**`,
so `db/site/tests` needs its own runner: the CI `site` job, or
`cd db/site && npm test` by hand).

Every row here needs a test tagged `[SITE-*]` in its `test()`/`it()` title
under `db/site/tests/`; `tests/tools/invariants.test.ts` fails the build
when an id has no tagged test, or a tag names an id not in this table.

| id | invariant | enforced by |
|---|---|---|
| SITE-1 | A session cookie round-trips (`sealSession`/`openSession`) for any payload and any non-empty secret; a tampered ciphertext, a session sealed under a different secret, an expired session, and a malformed token all open to `null` -- never throw. | `tests/server/session.test.ts` |
| SITE-2 | The `/api/v1/*` proxy's header matrix: `Content-Type`/`If-Match`/`If-None-Match`/`Idempotency-Key`/`Accept` forward; `Authorization`/`X-Client-Version` are added only as the proxy itself decides; `Cookie`/every `X-Akl-*`/every `X-Forwarded-*` request header, and `Set-Cookie`/`WWW-Authenticate` response header, are never forwarded in either direction, authenticated or anonymous; an authenticated response always carries `Cache-Control: private, no-store` regardless of upstream; `?wait=` is stripped before the request reaches the DB. | `tests/server/proxy.test.ts` |
| SITE-3 | A non-safe `/api/v1/*` request, or `POST /auth/logout`, without `X-Requested-With: akldb`, or with a cross-site `Sec-Fetch-Site`, is `403 csrf` and never reaches the DB (never clears the cookie); a safe (GET) request needs neither header. | `tests/server/proxy.test.ts`, `tests/server/discord.test.ts` |
| SITE-4 | No path outside `/api/v1/*` is proxied to the DB -- `/api/<not-v1>` and any other unmatched path 404 without calling `fetch`. | `tests/server/proxy.test.ts` |
| SITE-5 | Every user-facing string of 3+ words lives in `src/copy.ts`, which itself carries the `// COPY: sign-off pending` marker; no `.tsx` file outside it hardcodes one. | `tests/tools/copy-scan.test.ts` |
| SITE-6 | The admin UI (`pages/Admin.tsx`) is unreachable without a fresh `/auth/me` answer saying `admin: true` (`canSeeAdmin`, never a cached flag); every `admin*` function in `src/api.ts` targets `/api/v1/admin/*`. | `tests/tools/admin-gate.test.ts` |
| SITE-7 | The built client bundle (`vite build`'s `dist/`) has no reference to akl-db's real hostname anywhere outside the isolated `docs-content` chunk (the rendered `db/docs/adoption.md`, whose whole job is to quote it) -- the application code (session/proxy/api/pages) only ever reaches the DB through `DB_BASE_URL` at the server edge. | `tests/tools/no-hostname-leak.test.ts` |
| SITE-8 | Every var/secret this Worker reads (`wrangler.toml`'s `[vars]`, plus `DISCORD_CLIENT_ID`/`DISCORD_CLIENT_SECRET`/`SESSION_SECRET`) has a `README.md` row, and every row names something actually read in `server/`. | `tests/tools/readme-vars.test.ts` |
| SITE-9 | Nothing under `db/site/src` or `db/site/server` resolves an import into `db/src/**`, `db/formats/**`, or `web/src/**` (no `@akl/core`) -- the site is a client of the public wire only, per `db/tests/tools/boundary.test.ts`'s `LDB-G5` extension. | `tests/tools/no-db-src-import.test.ts`, `db/tests/tools/boundary.test.ts` |
| SITE-10 | An upstream `401 token_invalid` on an authenticated proxied request clears the session cookie and answers `401 {error:"reauth"}` without ever retrying (no refresh token is kept); an anonymous `401` passes through unchanged. | `tests/server/proxy.test.ts` |
| SITE-11 | A rendered `link` is used only if it re-parses as `https:` client-side; the visible text is always the hostname, never the raw string (H17). | `tests/src/safelink.test.ts` |
| SITE-12 | The site never links out to akl.gg and never renders a layout as a board: the built bundle contains no `akl.gg` literal and no board component; a layout page shows the stored format as plain text (canonical JSON). | `tests/tools/no-hostname-leak.test.ts` |
| SITE-13 | Every admin* mutation in `src/api.ts` goes through the shared `request()` wrapper (never a bespoke `fetch`), lands on a path under `/api/v1/admin/*`, and carries the CSRF header `X-Requested-With: akldb`; every admin* read also targets `/api/v1/admin/*`. | `tests/src/admin-csrf.test.ts` |
| SITE-14 | An `If-Match` header is sent on every rev'd write built by `src/api.ts` (`renameLayout`/`deleteLayout`/`transferLayout`) with the exact token the caller supplied, and is never sent by a like, `link`, `restoreLayout`, or any admin* builder. | `tests/src/ifmatch-builders.test.ts` |
| SITE-15 | No `window.confirm`/`alert`/`prompt` (or the bare global form) appears anywhere under `src/**` -- every destructive action confirms in place with its own inline confirm row. | `tests/tools/no-dialogs.test.ts` |
| SITE-16 | The production bundle (`vite build`'s `dist/`) contains no reference to the dev-only `?mock=admin`/`?mock=owner` QA switch (`src/lib/devMock.ts`) -- neither its distinctive strings nor its exported function names appear in any emitted chunk. | `tests/tools/no-dev-mock.test.ts` |
| SITE-17 | Author-name resolution (`src/lib/authorNames.ts`'s `resolveAuthorName`) is pure and total: any id -- known, unknown, empty, `null`, or `undefined` -- resolves without throwing, falling back to the id itself (or `""` for no id) whenever it isn't in the cached `/v1/authors` map. | `tests/tools/author-names.test.ts` |
| SITE-18 | The moderation console (`pages/Admin.tsx`'s tab bar and every tab's content) is absent from the rendered output entirely -- not merely CSS-hidden -- whenever a fresh `/auth/me` answer does not say `admin: true` (signed out, or signed in as a non-admin); an admin sees the tab bar and the default tab's content. | `tests/tools/admin-render.test.ts` |
| SITE-19 | The Event log pages backwards from the head sequence (`/v1/meta.seq`): the requested windows partition (0, head] exactly, descending, adjacent, and the first window contains the newest event. | `tests/src/eventlog.test.ts` |
| SITE-20 | The Home list's whole row navigates to the layout on an unmodified click landing anywhere in it (a single real `<a>` -- `akl-row-link` -- CSS-stretched over the `<tr>`, keyboard-reachable in the normal tab order); a modified click (meta/ctrl/shift/alt, or a non-left button) is left alone -- `preventDefault()` is never called and the route never changes, so the browser's own new-tab behavior proceeds; a link nested inside the row (the Owner column) still stays independently clickable above the stretched overlay. | `tests/src/router.test.ts`, `tests/tools/row-link.test.ts` |
| SITE-30 | `/adoption.md` is served byte-identical to `db/docs/adoption.md` after a build (`scripts/build-docs.mjs` writes both from the same read, verbatim, into `src/generated/docs.html.ts`'s `adoptionMarkdown` and `public/adoption.md`, which Vite copies into `dist/` untouched). | `tests/tools/docs-guide.test.ts` |
| SITE-31 | The Docs page's on-page endpoint brief lists exactly the routes registered in `db/docs/adoption.md` §9's own endpoint table — no more, no fewer — parsed at build time (`scripts/build-docs.mjs`'s `buildEndpoints`), never hand-copied. | `tests/tools/docs-guide.test.ts` |
| SITE-32 | The Docs page's "Copy as Markdown" button's clipboard payload is byte-identical to the markdown served at `/adoption.md`. | `tests/tools/docs-guide.test.ts` |
| SITE-33 | Every label on both W1c sequence diagrams (auth+ownership, trusted client) fits its own lane/arrow/self-loop span, in `src/ui/diagrams/sequence.ts`'s own geometry, without needing more than `MAX_SQUEEZE` (18%) `textLength` compression — a label that can't fit even at that squeeze fails the build rather than rendering clipped or illegibly squeezed. | `tests/ui/diagrams.test.ts` |
| SITE-34 | The Docs page (`src/pages/Docs.tsx`) has exactly one `<h1>` (the rendered guide's own leading heading is demoted to `<h2>` at build time), and every one of its table-of-contents anchors resolves to a real `id` on the same page. | `tests/tools/docs-guide.test.ts` |
| SITE-21 | The likes wire is `{ user_ids: string[] }` exactly as `db/tests/fixtures/db-responses/likes.json` records it; `isLikedBy` reads that key and never throws on any input. | `tests/src/likes.test.ts` |
| SITE-22 | Every routed page renders inside one `Errored` boundary (Solid 2's ErrorBoundary) below the Header, so a page error shows an inline message with a retry and never disposes the shell (header/nav keep working). | `tests/tools/error-boundary.test.ts` |
